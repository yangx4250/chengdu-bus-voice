# cd-bus · 成都公交到站语音播报

查成都公交的**实时到站**，并用中文语音念出来：还有几站、大约几分钟、是不是马上进站。

支持成都（含区县）与都江堰；其它城市的坐标会被直接拒绝。

```
$ cd-bus line 16路 --stop 天府广场南
16路 · 天府广场南站 （22:02:42 实时）
  最近  还有  3 站 · 约 2850 米 · 还有 3 站，约 9 分钟 · ETA 约 9 分钟
  第2辆  还有 14 站 · 约 7932 米 · 还有 14 站 · ETA 约 25 分钟

🔊 播报文案：16路，天府广场南站，最近一辆还有 3 站，约 9 分钟；下一辆还有 14 站。开往火车南站公交站。
```

## 1. 为什么不直接用那个 gist

你给的 [gist](https://gist.github.com/Ancientwood/774898f4a3fac8a36dad3c466d4e4fdd) 是一个 PHP 版车来了客户端，调的是老 App 接口
`api.chelaile.net.cn/bus/line!lineDetail.action` 这类地址。实测该接口族**已经整体停服**：

```
**YGKJ{"jsonr":{"status":"12009","errmsg":"该版本已不提供服务，请前往应用市场升级至最新版"}}
```

换 `v=5.50.4 → 7.0.0`、`s=android/ios/web`、补上 sign 都还是 12009，所以照抄不再可用。

现在还能用的是**车来了微信小程序**那套接口（社区逆向，2026 年仍在维护）：

| 项目 | 值 |
|---|---|
| 入口 | `https://web.chelaile.net.cn/api/bus/` |
| 签名 | `cryptoSign = md5(` `"k"="v"&…` `+ "qwihrnbtmj"` `)` |
| 返回 | `encryptResult = base64( AES-256-ECB(json) )`，key = `FF32AE65FBFD19414EAAFF6291A54B42` 的 ASCII |
| 关键参数 | `s=h5 & wxs=wx_app & src=weixinapp_cx & v=3.11.28 & scene=1256 …` |
| 城市 | 成都 `cityId=007`，线路 `lineId` 前缀 `028` |

本项目把这套协议封在 [`lib/chelaile.mjs`](lib/chelaile.mjs) 里，**零依赖**，只用 Node 内置的 `fetch` 和 `crypto`。

> 这套参数属于公开逆向成果，官方随时可能改版；接口失效时会明确报错，不会静默返回错数据。

## 3. 用法

```bash
cd-bus near
cd-bus near --lat 30.6570 --lng 104.0650 --limit 4
cd-bus line 1路                        # 没给 --stop 时，列沿线站点
cd-bus line 1路 --stop 大业路
cd-bus line 1路 --stop 大业路 --speak   # 同时发声
cd-bus line 1路 --stop 大业路 --dir 1   # 反方向
cd-bus stations 16路
cd-bus say "测试一下语音"
cd-bus watch 16路 --stop 天府广场南 --every 60
```

参数：

| 参数 | 说明 |
|---|---|
| `--lat` `--lng` | 坐标，默认天府广场 `30.657, 104.065`；也可用环境变量 `CD_BUS_LAT` / `CD_BUS_LNG` |
| `--stop` `--order` | 站名（支持包含匹配）或站点序号 |
| `--dir 0/1` | 线路方向（0 上行、1 下行） |
| `--speak` | 出声。`line`/`near` 默认只打印文字，`watch` 默认出声 |
| `--voice` | `auto`（默认）\| `termux` \| `online` \| `system` \| `off` |
| `--json` | 输出原始 JSON，方便接别的脚本 |
| `--every` | `watch` 刷新间隔秒数，默认 60 |

### 盯站自动播报（`watch`）

每 `--every` 秒刷新一次，满足任一条件就播报：

- 车辆 ≤ 2 站，或 ETA ≤ 150 秒 → **立刻播报**（状态从"不紧急"变成"紧急"时触发一次，不重复刷屏）
- 距上次播报超过 5 分钟 → 播报一次当前状态

播报例句：
`请注意，16路即将进站。16路，天府广场南站，最近一辆还有 1 站，约 1 分钟；下一辆还有 12 站。开往火车南站公交站。`

## 4. 语音后端

| 后端 | 条件 | 表现 |
|---|---|---|
| `termux` | 装了 Termux:API（`termux-tts-speak`） | 调系统 TTS 直接念，离线、即时 |
| `system` | macOS `say` / Linux `espeak-ng` | 桌面环境直接念 |
| `online` | 能访问 translate.google.com | 合成 mp3；有播放器就播，没有就落盘 |
| `off` | — | 只打印文案 |

`auto` 从上往下挑第一个可用的。

**本机（Redmi 2211133C）现状**：没装 Termux:API，系统里也没有中文 TTS 引擎
（`termux-tts-speak` 不存在、`settings secure tts_default_synth` 为空），
所以 `auto` 会落到 `online`：**文案和 mp3 都会生成**，但 Shell 侧没有可调用的播放器，
只能拿到文件手动播放。

要在手机上听到真正的"播报"，二选一：

1. 装 **Termux:API**（装完 `pkg install termux-api`），`cd-bus` 会自动走 `termux` 后端，完全离线；
2. 装任意中文 TTS 引擎（如讯飞语记/Google TTS），再在支持 `speechSynthesis` 的 WebView/浏览器里念——
   这条路更适合做随身播报 App，而不是命令行。

生成的 mp3 在 `~/.cache/chengdu-bus/`，可以直接拖进任意播放器。

## 5. "只要成都"是怎么保证的

1. `assertChengdu()` 用坐标反查车来了城市列表，不是 `cityId=007` 直接抛错
   （例：`✗ 当前位置属于「北京」，本工具只播报成都公交信息。`）；
2. 线路搜索结果再过一道 `lineId` 前缀 `028` 的过滤，地铁（`subwayV2=1`）也滤掉；
3. 默认坐标就是天府广场，不传坐标时也只会查成都。

③ 缓存取「最准」的那条而不是「最新」的；
④ 实时点太差（>200 米）而缓存更准时，用缓存并标「缓存位置」。
前端同步：定位超时 5 秒提到 8 秒（5 秒内 GPS 常常还没收敛），
新点精度比旧点差 2.5 倍以上时不覆盖（避免站名乱跳）。

### 盯站不播报的排查路径（v9.20 定案）

**症状**：心跳能正常播报，盯站完全不播（前台也不播）。

这个对比本身就是关键线索 —— 心跳服务**没有任何判断**，拿到就播；
盯站服务却有一层「界面可见就交给页面播」的逻辑。顺着查下去发现了死结：

```java
// WatchService.announce()
if (MainActivity.frontAndScreenOn(this)) { return; }   // 服务不播

// 页面 watchTick 的定时器
setInterval(function () {
  if (document.hidden) return;                          // 页面也不播
  watchTick();
}, 30000);
```

息屏时 Activity **仍然是 resumed**，`VISIBLE = true` → 服务以为页面会播就跳过；
而页面的 `document.hidden` 为真 → 也跳过。**两边都跳过，一句都不念。**

**v9.18 的修法**：删掉所有「交给对方播」的分支，**播报只保留一条路径** ——
一律由服务播，页面只管界面。

**v9.20 补的兜底**：服务万一没起来/被杀，前台就彻底没声了。所以页面加了判断：

```js
if (first && !document.hidden && !svcRunning) { 页面播 }   // 仅当服务没跑
```

服务在跑时页面绝不播（不重复），服务没跑时页面补上（不静默）。

**三个诊断工具**（设置 → 语音自检）：

| 工具 | 用途 | 结论怎么读 |
|---|---|---|
| 后台心跳 | 验证保活+播报链路 | 一直在响 = 链路没问题 |
| 盯站诊断模式 | 每轮念「第 N 次轮询」 | 能听到 = 服务在跑，问题在触发条件 |
| 通知栏 | 显示参数缺失/查询失败 | 不再静默 return |

> 教训：**两个组件互相「让」一件事，就一定会出现没人做的情况。**
> 播报这种关键路径必须只有一条，兜底要么不做，要么用「对方明确失效」来触发。

### 后台心跳测试（v9.17）

设置 → 语音自检里多了一个按钮：**「开始后台心跳（每 30 秒报一次）」**。
点开后每 30 秒念一句「后台心跳第 N 次」，用来**直接验证**锁屏/后台时播报还活不活。

**为什么单独做一个服务，而不是页面定时器**：页面（WebView）的 `setInterval`
在息屏后会被系统冻结，用它测等于「测了个假问题」——它必然停。
心跳服务 `HeartbeatService` 走的是**和真实盯站播报完全相同的路径**：

```
前台服务 + PARTIAL_WAKE_LOCK（每轮续期）+ Speech（系统 TTS / 在线合成）
```

**怎么用这张诊断表**：

| 锁屏后的现象 | 结论 | 对策 |
|---|---|---|
| 每 30 秒都能听到「第 N 次」 | 保活链路没问题 | 那问题在盯站逻辑，不是后台 |
| 响几次后彻底停 | 系统把服务清了 | 点「加入电池优化白名单」 |
| 一次都没响 | 服务没起来或音频被掐 | 看面板的 `✅/❌` 结果 |

面板上会实时显示：`心跳中 · 已播 N 次 · 上次 X 秒前 · ✅ 系统 TTS`。
按钮文案在「开始 / 停止」之间切换，随时可以关掉。

### 盯站新增「已到站」播报（v9.16）

原来的播报节点是 **10 分钟 → 5 分钟 → 还有 2 站**，最后一句是「马上就要进站」。
问题在于 `stationsAway <= 2` 把 **0 站（车已到站）** 也算进去了，播的还是「快到了」——
车明明停在面前，却听不到一句「到了」。

现在拆成独立节点：

| 节点 | 条件 | 播报 |
|---|---|---|
| 10 分钟 | `0 < eta ≤ 600` | 大约 10 分钟到站 |
| 5 分钟 | `0 < eta ≤ 300` | 大约 5 分钟到站 |
| 还有 2 站 | `0 < away ≤ 2` | 还有 2 站 / 下一站就下车 |
| **已到站** | `away == 0` 或 `eta == 0` | **已到站**（通知同步变成「站名 · 已到站」） |

前后台两套逻辑同步改（页面 `watchTick` 播「已到站，请准备上车」，
服务 `WatchService` 播「已到站」），各用一个 `spokeArrived` 标志保证**只播一次**；
换车（`busId` 变了）或重新开始盯站时标志复位。

### 到站后自动结束下车提醒（v9.14 / v9.15）

原来到站只是「停 GPS + 停轮询」，**服务还在前台跑、通知常驻、提醒条一直挂着**，
`localStorage` 里的提醒也没清 —— 下次打开 App 又会弹出来，得手动点「取消」。

**v9.14 的第一版没生效**，原因是个死结：到站时页面把轮询自己停掉了

```js
if (alight.arrived && alightTimer) { clearInterval(alightTimer); }   // 停了
if (alight.arrived && !info.running) { alightArrivedCleanup(); }     // 永远到不了
```

轮询都停了，还怎么等下一次读到 `running=false`？清理逻辑成了死代码。

**v9.15 改成「到站播报完立刻收尾」**，不再依赖后续轮询：

1. 到站那一轮先播「到站了，请下车」（播报放在清理**之前**，否则 `eventText` 被清掉就不念了）；
2. 紧接着 `alightArrivedCleanup()`：**隐藏提醒横幅、移除首页卡片、清 `localStorage`、
   停掉原生服务**，状态栏提示「已到站，下车提醒自动结束」；
3. `alightDest` / `alightLine` 置空后，站点行的 🔔 自动恢复成可再次点开的状态。

原生侧同步调整：`finishAndAutoCancel(3 * 1000)` —— 只留 3 秒让语音播完就停服务，
不再等 12 秒（页面那边已经立刻收尾了，服务早点停更干净）。

> 关键教训：**「到站即终态」的清理逻辑不能挂在「后续轮询」上** ——
> 到站的同时把轮询关掉，那条清理分支永远不会执行。

### 后台与息屏播报修复（v9.13）

「锁屏后就不播报了」不是一个原因，是**四个问题叠在一起**：

**1. 息屏后 CPU 休眠，Handler 定时器被冻结**

`Handler.postDelayed` 在 Doze 下会停摆，等亮屏才一次性补跑——表现就是「锁屏全程没声，一解锁连着响」。
现在两个服务（`WatchService` / `AlightService`）都持一把 `PARTIAL_WAKE_LOCK`
（[`WakeKeeper.java`](app/src/com/chengdu/bus/WakeKeeper.java)），每轮 tick 续期 2 分钟，
只保 CPU 不亮屏，耗电很低。服务销毁时立即释放，不会漏一把锁把电池耗干。

**2. 息屏时把播报错误地「交给页面」→ 谁都没念**

原来的判断是 `if (MainActivity.VISIBLE) return;`。但**息屏时 Activity 仍是 resumed**，
`onPause` 不触发，`VISIBLE` 一直是 `true` —— 于是服务以为页面会播，而页面的 JS 定时器
早已被冻结。结果两边都没声音。
新增 `MainActivity.frontAndScreenOn()`，**同时**要求「界面可见 + 屏幕亮着」
（`PowerManager.isInteractive()`）才让页面播，否则服务自己念。

**3. 没有音频焦点，息屏时被降权/静音**

原来直接用 `USAGE_MEDIA` 播，若后台有音乐在放会被压低甚至静音。
现在统一用 `USAGE_ASSISTANCE_ACCESSIBILITY + CONTENT_TYPE_SPEECH`，
播报前 `requestAudioFocus(AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK)`，播完释放。
TTS 和在线合成（MediaPlayer）两条路径都走这套属性。

**4. 系统把后台服务清掉**

- 服务加 `android:stopWithTask="false"`（划掉任务卡片也不停）；
- `WatchService` 前台服务类型从 `dataSync` 改为 `dataSync|location`（Android 14+ 对 `dataSync` 有息屏限制）；
- 补 `FOREGROUND_SERVICE_LOCATION` 权限；
- 设置面板新增**「加入电池优化白名单」**按钮，调系统标准弹窗（国产 ROM 默认清后台，这步最关键）。

**怎么确认修好了**：设置面板新增「后台播报自检」——

```
盯站服务    运行中
唤醒锁      已持有（息屏可播）
上次轮询    12 秒前
上次播报    1 分钟前 · ✅ 系统 TTS
```

锁屏等几分钟再打开看这几行：**上次轮询**如果一直不动，说明服务被系统杀了
（去点「加入电池优化白名单」）；如果轮询在动但没声音，看「上次播报」的结果。

### 点进车辆看沿途各站（v1.2）

首页（附近站点 / 线路查询结果）里每条「X路 → 方向 还有N站」都可以点开：

- 顶部列出这条线**在途的所有车辆**（车牌 + 还有几站），点一下切换；
- 下面按站序列出**这辆车到往后 10 个站**的到站时间（分钟 + 时刻）；
- 车已经开过的站置灰显示「已过」，≤150 秒的标红；
- **点车辆跳转后自动滑到离我最近的那一站并标注**：用当前定位（`state.fix`）和
  各站经纬度算球面距离，把最近的一站标上绿色边框和「离我最近 · N 米」徽标，
  并滚到视口中央；没有定位时退回打开的那一站（站序 `fromOrder`）；
- **线路页的站名条同样标注**：离我最近那一站的芯片加绿色描边 + `最近` 徽标，
  进入线路页时自动横向滚到它（点搜索指定了站名时不抢滚动位置）；
- 滚动用 `scrollElementIntoView()`：先算目标位置再 `window.scrollTo`，
  并延迟 350 ms 补滚一次——WebView 里列表刚重建时布局未稳，单靠
  「平滑滚动」那个 API 会静默失效（这也是上一版看起来"没反应"的原因）；
- 左上「← 返回」或系统返回键回到首页（详情页里按返回不会退出 App）。

接口本身**不提供**「单车逐站时间」（`travels` 只有一个目标站），所以做法是：
对从当前站往后的每一站各查一次 `line!encryptedBusDetail`，再用 `busId` 把同一辆车在不同站的记录串起来。
`window=10` 就是 10 次请求、4 路并发，实测 **8 站 480 ms**（`stationMatrix()`）。单站失败只丢那一格，不影响整页。

### 为什么默认用 WebView 出声（v1.8）

在本机（Redmi 2211133C / HyperOS）实测四条路径：

| 路径 | API | 结果 |
|---|---|---|
| 系统音效 | `ToneGenerator` | ✅ 有声 |
| 网页播放 | WebView `<audio>`（Chromium） | ✅ 有声 |
| 音频文件 | `MediaPlayer` 读本地 WAV/MP3 | ❌ 静音 |
| PCM 直出 | `AudioTrack` | ❌ 静音 |

同一个媒体音量下，「App 自建音频轨」被静音、而系统合成器和 Chromium 正常 —— 是 ROM 侧的音频策略，
不是 TTS 或文件格式的问题。所以 v1.8 起**语音默认走 WebView**：

```
Java 合成 mp3 → base64 → WebView <audio> 播放
```

### 播报没声音怎么查（v1.5）

底部 **🔧** 打开语音自检面板，会直接列出：

| 项 | 说明 |
|---|---|
| 语音后端 | 系统语音 / 在线语音 |
| 系统 TTS | 可用 / 不可用（不可用就走在线合成） |
| 已装引擎 | `TextToSpeech.getEngines()` 的结果，空就是没装任何语音引擎 |
| 媒体音量 | `x / 15`，为 0 会标红提示（静音模式最常见的坑） |
| 铃声模式 | 静音 / 振动 / 正常 |
| 最近结果 | 上一次播报走到哪一步、报了什么错 |

面板里的按钮：

- **调大媒体音量**：把 STREAM_MUSIC 设到 80%（带系统音量条）；
- **测试音·播放器**：本地生成 1.5 秒 660Hz wav，`MediaPlayer` 播放，**不联网**；
- **测试·PCM 直出**：绕开播放器，直接用 `AudioTrack` 写 PCM；
- **测试·系统音效**：再用 `ToneGenerator` 响一声（第三条完全独立的路径）；
- **试播一句话**：走完整语音链路（系统 TTS → 在线合成）。

再加一条**网页播放**：`测试·网页播放` 用 JS 现场生成 WAV 交给 WebView 的 `<audio>`（Chromium 音频栈，和系统播放器不是一套）。
面板底部的「语音走 WebView」开关会把所有播报改成：Java 合成 mp3 → base64 → WebView 播放。

三条测试路径的用途：**只要有一条能听到**，就说明扬声器和音量没问题，问题在具体那条链路；
**三条都听不到**，就不是 TTS/播放器的事——要么媒体音量为 0，要么声音被路由到蓝牙/耳机，面板上的「输出设备」会写出来。

另外每次点播报后，底部状态栏会回显最近结果，例如
`在线合成 已启动（媒体音量 0，playing=false）⚠ 媒体音量为 0，请按音量键调大`。

「同站其它」里却出现「716路 还有 21 站」——那是**对面站台**往花园公交站的车。

根因在合并站台的条件：

```js
stationId 相同 || nameDistance(站名) <= 1     // 对面站台名字几乎一样，被合并了
```

对面站台的名字通常只差一个字甚至完全相同，`nameDistance ≤ 1` 把它们全并进来，
于是两个方向的到站数据混在一起。

现在用 `nearby` 返回的 `toward`（该方向的终点站名）做方向校验：

- **站台合并时**：名字/id 相近但 `arrivals[].toward` 与当前详情页方向不符 → 不合并；
- **到站数据**：合并后仍逐一检查 `arrivals[].toward`，方向不符的丢弃；
- 没有实时数据的站台保留（它可能只是线路列表，无法判方向）。

原则：**宁可少显示，也不显示反方向** —— 反方向的车对你没有意义，还容易误导。

### 后台播报修复 + 任意站盯站（v7.1）

**后台不播的原因**：服务是靠 `visibilitychange` 在退后台那一刻启动的，WebView 往往在事件派发前就被挂起，
服务根本没起来；回到前台 JS 恢复后又由页面播报，看起来就像"只有回前台才响"。

改法：**盯站一开始就启动前台服务**，播报统一由服务负责，JS 只更新界面状态（不再自己播）。

- 避免前后台两套播报逻辑重复；
- 服务目标写入 `SharedPreferences`，进程被系统杀掉后 `START_STICKY` 重启也能恢复盯站。

**任意站盯站**：详情页每个站点行右侧多了 📌，点它就把盯站切到那一站（线路不变、站点换掉），
顶部盯站条会同步显示新的「线路 · 站 · 方向」。

### 后台常驻 + 盯站播报节点（v7.0）

**后台常驻**：App 退到后台时，会启动前台服务 `WatchService`（通知栏常驻），每 30 秒查一次盯站的到站情况，
用系统 TTS 播报。回到前台后自动停掉服务，改由页面自己盯——两边不会重复播。

- 需要 `FOREGROUND_SERVICE` / `FOREGROUND_SERVICE_DATA_SYNC` / `POST_NOTIFICATIONS` 权限；
- Android 13+ 会单独弹一次通知权限（用于常驻通知）；
- 为什么必须原生：WebView 的 JS 定时器在后台会被系统挂起，纯 JS 盯不住。

**盯站播报节点**：同一辆车只在三个节点各播一次（不再每 5 分钟念一次）：

| 条件 | 播报 |
|---|---|
| ETA ≤ 10 分钟 | `X路，Y站，大约 10 分钟到站。` |
| ETA ≤ 5 分钟 | `X路，Y站，大约 5 分钟到站。` |
| 剩余 ≤ 2 站 | `X路，Y站，还有 2 站到站。`（0 站时说「马上就要进站」） |

车换了（`busId` 变化）就重置这三个标记，避免新车不再播报。

- 切换时用**站点的 `sId`**把这个站带过去 —— 同一天然站在两个方向上是同一个 `sId`，只是 `order` 不同

### 定位是怎么取的（v1.1）

`Locator.java`，宁可多等几秒也不拿旧数据蒙人：

1. 2 分钟内的 `lastKnownLocation` → 直接用（秒回）；
2. 否则同时向 `NETWORK` / `GPS` 请求一次定位，最多等 12 秒；精度 ≤50 米提前结束，
   否则取这段时间里最准的一条；
3. 还拿不到就退回最旧的缓存位置，并标记 `stale`（界面会写「缓存位置」）。

授权结果通过 `onRequestPermissionsResult` 回传页面（`window.cdBusPermission`），
用户点「允许」后自动重跑定位，不用手动刷新。**没权限时不再假装成功**，而是先停下等授权。

### 自己重新打包

> **改完代码后务必重新打包**：`app/`（Java、Manifest、`res/`）或 `app/assets/`（界面、交互逻辑）
> 有任何改动，都要**再跑一次 `./build-apk.sh`**。APK 里的界面是打进包的 `assets/index.html`，
> 只改源码不会自动生效——手机上跑的还是旧包里的旧资源。每次改完重新构建、签名后再装。

`build-apk.sh` 是纯命令行流水线，不依赖 Gradle/Android Studio：

```
javac(17) → d8 → aapt(资源/清单) → tools/zipalign.py(4 字节对齐) → apksigner
```

```bash
./build-apk.sh
# 需要 ../sdk/android.jar（Android 13 platform，从 dl.google.com 的 platform-33-ext3_r03.zip 里取）
```

在这台设备上从零装工具链的坑（记录备查）：

- Termux 的 .deb 里 preinst 脚本写死了 `/data/data/com.termux/...`，`dpkg -i` 会失败 →
  用 [`local-install.sh`](local-install.sh) 手动铺包并只改**文本脚本**的 shebang（不要 sed 二进制！）。
- JDK 解压后 `bin/java` 要自己补 wrapper；`libjvm.so` 依赖 `libandroid-shmem.so`。
- `aapt` 依赖 `libpng16.so` / `libzopfli.so`。
- `javac` 用 `-bootclasspath android.jar` 时不能用 lambda（`LambdaMetafactory` 不在 android.jar），代码里已全部改成匿名内部类。

### App 结构

```
app/
├── AndroidManifest.xml        包名/权限/入口 Activity
├── res/drawable-*/            桌面图标 48/72/96/144/192px（由原图裁切生成）
├── res/values/strings.xml     应用名「成都公交」
├── assets/index.html          全部界面与交互逻辑（单文件）
└── src/com/chengdu/bus/
    ├── MainActivity.java      WebView 壳 + 定位权限
    ├── BusBridge.java         JS 桥：后台线程查询 + poll 轮询结果
    ├── ChelaileClient.java    协议：签名 / AES 解密 / 线路 / 到站 / 附近
    └── Speech.java            系统 TTS 优先，回退在线合成 + MediaPlayer
```
